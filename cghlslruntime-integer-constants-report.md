# Report: Integer Constants Instead of Enums in `CGHLSLRuntime.cpp`

File: `clang/lib/CodeGen/CGHLSLRuntime.cpp`
Date of report: 2026-10-21

## 1. Summary

- The practice started on 2025-06-04 in PR [#138530](https://github.com/llvm/llvm-project/pull/138530).
- The author was Nathan Gauër (`Keenuts`).
- All of the integer constants are SPIR-V values: decoration IDs, BuiltIn IDs, and address spaces.
- Reviewers asked about the numbers four times. In the three earlier PRs (#138530, #153424, #210116), the authors added or changed a comment. They did not add an enum.
- In the recent PR (#233504), the concern is not resolved. The PR is open. The author said that a clean-up must be a separate change.
- One author (`farzonl`) thought about an enum in July 2026. He did not add one, because the enum did not seem to belong in an HLSL file.
- The reason for the practice is this: the SPIR-V enums are generated by TableGen in the SPIR-V backend. Clang CodeGen cannot use them.

## 5. Causes

1. **The enums are not available.** The SPIR-V backend generates `Decoration` and `BuiltIn` enums with TableGen. See `llvm/lib/Target/SPIRV/MCTargetDesc/SPIRVBaseInfo.h`. These enums are private to the backend. Clang CodeGen cannot include them.
2. **There is no shared header.** Clang does not use SPIRV-Headers. `clang/lib/Sema/SemaSPIRV.cpp` has a small local enum (`spirv::StorageClass`). It has this note: "FIXME: either use the SPIRV-Headers or generate a custom header using the grammar (like done with MLIR)."
3. **Each PR was small.** Each PR added one or two new values. In the earlier PRs, a comment was the simplest fix. No single PR owned the clean-up.

## 6. Notes

- The address spaces `7` and `8` do not need new enums. Clang already maps `LangAS::hlsl_input` to `7` and `LangAS::hlsl_output` to `8` in `clang/lib/Basic/Targets/SPIR.h`. The same file (`CGHLSLRuntime.cpp`) already uses `Ctx.getTargetAddressSpace(LangAS::hlsl_input)` in another function. The hard-coded `7` and `8` can use this method.
- The decoration and BuiltIn IDs need a shared source. Possible options:
  - Add a small enum header in Clang (like `SemaSPIRV.cpp` does).
  - Move the TableGen-generated enums to a location that Clang can use.
  - Use SPIRV-Headers.
- `addSPIRVBuiltinDecoration` takes an `unsigned` BuiltIn ID. `HLSLVkExtBuiltinInputAttr` and `HLSLVkExtBuiltinOutputAttr` also pass integer IDs from user source. A strict enum type must still accept these user values.
